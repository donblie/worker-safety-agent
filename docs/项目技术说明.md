## 一、项目概述

### 1.1 背景与问题

建筑行业是我国安全生产形势最严峻的行业之一。建筑施工事故中，超过70%与人的不安全行为直接相关。一线工人的安全知识匮乏是导致不安全行为的重要原因：

- **安全规范门槛高**：JGJ 80、JGJ/T 46等国标行标术语密集、条文数百条，工人看不懂也记不住
- **安全员覆盖有限**：一个安全员管几百号工人，无法做到"随时随地有人问"
- **紧急情况容易慌**：事故发生时，工人往往不知道第一步该做什么、绝对不能做什么

**一句话说清问题：安全规范躺在文件柜里，不在工友口袋里。**

### 1.2 项目定位

**工友安全守护Agent** 是一款面向建筑工地一线工人的AI安全智能助手。它整合了DeepSeek文本大模型和Qwen-VL视觉大模型，覆盖安全知识问答、工地隐患拍照识别、安全培训内容生成、应急处理指导四大场景，并新增单Agent对话入口（Function Calling自动调度工具），流式输出让回答逐字呈现。部署在Streamlit Cloud上，手机浏览器打开即用，无需安装APP。

### 1.3 核心价值

| 维度 | 价值 |
|------|------|
| **降低门槛** | 工人用大白话提问，AI用通俗语言回答，消除专业壁垒 |
| **视觉巡检** | 手机拍张照片，AI自动识别安全隐患并给出整改建议 |
| **培训自动化** | 选工种定主题，秒级生成培训大纲+详细内容+配套测验 |
| **应急有底气** | 覆盖14类事故的分步指导，自动生成上报报告，一键拨120 |
| **全天候覆盖** | 7×24小时在线，手机浏览器即开即用，弥补安全员人力不足 |

### 2.2 核心技术选型

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| **前端框架** | Streamlit | 纯Python，一套代码搞定前后端；自带移动端响应式；Streamlit Cloud免费托管 |
| **文本LLM** | DeepSeek (deepseek-chat) | 中文理解能力强；API成本极低；OpenAI兼容格式，迁移成本低 |
| **视觉LLM** | Qwen-VL (qwen-vl-max) | 阿里云通义千问视觉模型，中文场景理解优秀；OpenAI兼容Vision API |
| **知识检索** | TF-IDF关键词检索（char ngram 1-2） | 零外部依赖、毫秒级响应、云端稳定不崩；对规范条文这类术语固定的领域文本匹配精准；预留BGE语义嵌入接口，知识库扩充后可无缝升级 |
| **文本分块** | 自定义分段器 | 按段落+字数边界智能切分，保持语义完整；500字/块，50字重叠 |
| **LLM输出解析** | 自定义JSON提取器 | 花括号计数匹配法，处理代码块包裹、前后文字混排、嵌套对象等异常格式 |
| **响应缓存** | LRU内存缓存 + TTL过期 | 避免短时间内相同请求重复调用API；文本10分钟/图片30分钟过期 |
| **Agent调度** | Function Calling（DeepSeek工具调用） | 4个Tool（规范检索/照片分析/培训生成/应急指导），用户自然语言描述需求，Agent自动判断意图并调度工具 |
| **流式输出** | Server-Sent Events (stream=True) | 培训内容、问答回复逐字呈现，用户不用盯spinner等结果 |
| **日志追踪** | 结构化日志 | 记录每次API调用的服务商、模型、耗时、Token用量、成功/失败状态 |
| **运行环境** | Python 3.x | AI生态最完善，所有依赖库原生支持 |

### 2.3 双模型协同设计

本项目采用"文本+视觉"双模型架构，按场景智能路由：

```
用户输入 ──┬── 文字问题 ──→ TF-IDF检索 → DeepSeek生成 → 文本回答
           │
           └── 现场照片 ──→ 图片编码 ──→ Qwen-VL分析 → 结构化报告
```

**为什么用两个模型？**

- DeepSeek在中文文本理解和生成上性价比极高（¥1/百万tokens），适合高频率的文本问答
- Qwen-VL在中文场景的视觉理解上表现出色，适合工地隐患识别这种需要"看图说话"的任务
- 分离设计降低耦合——文本模块出问题不影响视觉模块，反之亦然

### 2.4 知识检索方案

项目采用 **TF-IDF关键词检索**，并根据知识库规模预留了语义嵌入升级接口：

| 方案 | 引擎 | 状态 | 特点 |
|------|------|------|------|
| 📋 **关键词检索（当前）** | TF-IDF (char ngram 1-2) | 生产使用 | 零外部依赖、毫秒级响应；对规范条文这类术语固定的领域文本匹配精准；云端稳定不崩 |
| 🧠 **语义检索（可扩展）** | BAAI/bge-small-zh-v1.5（384维） | 预留接口 | 语义理解强，"安全带咋挂"≈"安全带系挂方法"；知识库扩充到数千条时无缝切换 |

**检索流程：**
```
用户问题 → TF-IDF向量化(字符ngram) → 余弦相似度Top-3 → 过滤低分噪音(阈值0.08) → 拼接上下文 → DeepSeek流式回答
```

**为什么当前选 TF-IDF 而非 BGE？**

1. **规模匹配**：当前知识库为26个规范语义块，TF-IDF的关键词匹配已能精准命中，语义模型的优势（同义词理解）在小规模下不明显
2. **稳定性优先**：BGE底层依赖PyTorch（约800MB），在Streamlit Cloud免费版上会导致冷启动超时、内存不足崩溃风险；TF-IDF零依赖，秒级加载
3. **演进路径清晰**：知识库代码中已预留嵌入模型接口（`_use_embeddings`标志位），当规范文档扩充到数千条时，安装`sentence-transformers`即可无缝升级为语义检索

**设计考量：**

1. **零摩擦优先**：不安装 `sentence-transformers` 时系统照常运行（TF-IDF模式），适合快速部署和稳定演示
2. **缓存版本管理**：缓存文件携带 `_version` 标记，嵌入模型升级时自动重建索引，避免新旧格式不兼容
3. **阈值统一**：检索共用 `RETRIEVAL_MIN_SCORE = 0.08`，低于阈值的噪音自动丢弃，避免无关上下文干扰LLM

知识库规模：
- 6份建筑安全规范文档（高处作业、脚手架、临时用电、个人防护装备、模板工程、塔吊起重机械）
- 1份施工现场综合应急预案
- 共计26个语义块，TF-IDF字符级特征（char ngram 1-2）

## 三、功能设计

### 3.1 模块一：安全知识问答 💬

**场景**：工友遇到安全疑问，随时提问。

**处理链路**：
```
用户自然语言 → TF-IDF检索Top-3规范块 → 拼接上下文 → DeepSeek → 通俗回答（附规范出处）
```

**设计要点**：
- System Prompt设定"安全小海"人设——专业但说人话
- 检索无结果时自动降级为纯LLM回答，标注"仅供参考"
- 预制6个高频示例问题，一键点击
- 支持多轮对话历史
- 1.5秒防重复提交冷却

### 3.2 模块二：工地隐患识别 📷

**场景**：工友或安全员巡检时拍照，AI自动分析隐患。

**两种模式**：
| 模式 | 流程 | 适用场景 |
|------|------|---------|
| 📸 快速拍照 | 开摄像头→拍照→自动分析 | 现场快速巡检 |
| 📤 上传照片 | 选照片→补充描述→点击分析 | 事后详细分析 |

**处理链路**：
```
现场照片 → Base64编码 → Qwen-VL视觉分析 → 结构化JSON报告
```

**Qwen-VL逐项检查7大类**：人员防护、高处作业、临时用电、机械设备、物料堆放、基坑/边坡、消防安全

**输出内容**：
- 隐患列表（类型/严重等级/具体描述/整改建议/时限）
- 符合规范的地方（正向反馈）
- 高风险隐患自动标记"需立即行动"+红色脉冲警告

### 3.3 模块三：安全培训助手 📚

**场景**：安全员需要快速准备班组培训材料。

**可选参数**：
- 工种：15种（架子工、电工、焊工、起重工等）
- 主题：15个（高处作业、临时用电、消防安全等）
- 难度：基础 / 进阶 / 班组长

**处理链路**：
```
工种+主题+难度 → 检索相关规范 → DeepSeek生成 → 完整培训包
```

**输出内容**：
- 培训大纲（5-8个知识点）
- 每个知识点的：详细讲解 + 关键数据 + 常见错误
- 配套测验题（5道单选/判断，即时判对错）

### 3.4 模块四：应急处理指导 🆘

**场景**：发生紧急情况，工人需要立即知道怎么办。

**覆盖14类事故**：触电、高处坠落、物体打击、坍塌、火灾、中暑、机械伤害、化学品伤害、有限空间窒息、基坑进水、管涌、脚手架倒塌、塔吊倾覆、爆炸

**处理链路**：
```
选择事故类型 + 现场描述 → 检索应急预案 → DeepSeek → 分步指导
```

**输出内容**：
- ⚡ 第一件事（最关键）
- 📋 分步骤操作（每步：做什么+具体怎么做+为什么+特别警告）
- 🚫 绝对禁止事项
- 🚑 何时必须打120
- 📌 紧急情况控制后的后续步骤

**🆕 紧急上报功能**（自动生成报告）：
- 自动汇总事故类型、时间、人数、现场情况、已采取措施
- 🚨 一键上报 → 模拟通知安全员/项目经理/应急小组
- 📋 复制报告内容 → 粘贴到微信/钉钉群
- 📞 一键拨120（`tel:120`，手机端直接唤起拨号）

### 3.5 模块五：对话助手（Agent统一入口）🤖 🆕

**场景**：工友不想在多个页面间跳转，在一个对话框里自然描述需求，Agent自动判断意图并调度工具。

**核心机制**：基于DeepSeek Function Calling，Agent根据用户输入自动判断需要调用哪个工具：

| 工具 | 触发场景 | 示例输入 |
|------|---------|---------|
| `search_regulations` | 问安全知识、规范要求 | "高处作业安全带怎么挂？" |
| `generate_training_material` | 要求生成培训内容 | "帮架子工生成脚手架安全培训" |
| `get_emergency_guide` | 描述紧急/事故情况 | "有工友触电了怎么办？" |
| `analyze_construction_image` | 上传工地照片请AI分析 | "帮我看下这张照片有什么隐患" |

**处理链路**：
```
用户自然语言 → Agent分析意图 → Function Calling选择工具 → 执行工具 → 结果注入上下文 → LLM合成回答
```

**交互特点**：
- 用户用一句自然语言描述需求，无需选择功能模块
- Agent自动判断：这个问题需要查规范？需要生成培训？识别照片？还是紧急情况？
- 工具调用过程可视化（显示"📚 搜索安全规范..."等状态）
- 支持快捷提示和一键清除对话
- 侧边栏支持工地照片上传，Agent 自动调用视觉分析工具识别隐患

**与独立页面的关系**：
- Agent对话作为**快速入口**：一句话搞定
- 四个独立页面作为**深度模式**：完整参数配置、详细结果展示
- 两者共享同一套 core 模块，零重复代码

## 五、安全守卫设计

### 5.1 异常处理矩阵

| 异常场景 | 降级策略 |
|---------|---------|
| TF-IDF检索无结果 | 降级为纯LLM回答，标注"未在规范库中找到直接依据" |
| DeepSeek API超时 | 30秒超时，提示"服务繁忙，请重试" |
| DeepSeek API不可用 | 明确提示 + 引导联系安全员 |
| 流式输出中断 | 显示已生成内容 + "回答中断，请重试"，不丢已展示文本 |
| Qwen-VL分析失败 | 友好提示"无法识别，请确保照片清晰" |
| 图片格式不对 | 校验格式+大小，拒绝分析非JPG/PNG/WEBP |
| 图片内容非工地 | 拒绝分析，说明"暂不支持非工地场景" |
| 工友输入无关内容 | 80+安全关键词预过滤 → 非安全相关输入礼貌引导 |
| 快速连点 | 1.5秒冷却期，显示"请稍等X秒" |
| LLM返回非JSON | JSON提取器兜底——花括号计数匹配→尝试解析→失败则展示原始文本 |
| LLM返回JSON字段缺失 | Schema自动校验——`validate_and_fix_json()` 用默认值填充缺失字段，消灭"UI突然空白" |
| 知识库未就绪 | LLM prompt中追加"知识库未就绪，请标注"提示，确保回答诚实透明 |
| 相同问题重复提交 | LRU缓存命中——直接返回缓存结果，避免重复API调用和费用 |

### 5.2 错误检测机制

**API异常捕获**：`safe_api_call` 装饰器统一捕获 5 种 OpenAI SDK 异常（`APITimeoutError` / `AuthenticationError` / `APIConnectionError` / `RateLimitError` / `APIError`），返回对应中文降级话术。上层通过 `is_api_error_response()` 判断返回是否为降级消息，替代分散的 emoji 关键词匹配。

**JSON Schema 校验（🆕）**：`validate_and_fix_json()` 在 JSON 解析成功后校验必要字段。LLM 可能返回结构正确但字段缺失的 JSON（如 `training_generator` 少了 `quiz` 数组），该校验函数自动用默认值填充缺失字段并记录告警日志——消灭"解析成功但下游取 `result.get("steps", [])` 为空，UI 一片空白"的静默异常。

**对话上下文注入（🆕）**：安全问答模块在每次 LLM 调用前，自动注入最近 3 轮对话历史（最多 7 条消息），LLM 能够理解追问意图。"那脚手架的呢？"不再导致答非所问。

### 5.3 高风险输出审核

任何输出命中以下条件，强制追加人工审核提示：
- 隐患严重等级为"高"
- `requires_immediate_action == true`
- 紧急类型属于 [触电, 坍塌, 火灾, 爆炸, 有限空间窒息]

追加内容："🚨 此情况属于高风险，AI分析不可替代专业人员判断。请在采取行动前，务必报告现场安全员或项目经理。"

### 5.4 结构化日志与可观测性

所有API调用通过 `utils/logger.py` 记录：服务商、模型名、耗时(ms)、成功/失败状态、Token用量。异常通过统一日志输出，带时间戳和错误详情。检索过程记录查询词、命中数、最高相似度得分。生产环境可无缝切换至 Python `logging` 模块或外部监控服务。

## 七、创新点总结（对齐评审四维度）

本项目的创新不在于发明新算法，而在于将成熟技术以独特方式组合，解决一个被忽视群体的真实问题。以下从评审标准的四个维度展开。

### 7.1 创新性 — 维度交叉即创新

**土木工程 × AI应用**：从非CS专业视角出发，以"王师傅"（45岁、初中文化、会用微信不会打字）为真实用户画像，从需求定义阶段就不再是"技术自嗨"。

**文本模型 × 视觉模型**：一套系统同时驾驭DeepSeek和Qwen-VL，按输入类型（文字/照片）智能路由，而非简单堆砌。两个模型各自的超时、异常、兜底策略相互独立——一个挂了另一个不受影响。

**检索 × 生成**：TF-IDF规范检索为LLM提供事实锚点。不是让模型凭记忆回答安全问题，而是"查了规范再说"——这在安全领域意味着：回答可溯源、可核实、可追责。

**应急指导 × 自动上报**：从"AI告诉你"到"AI帮你做"。应急模块生成报告→一键上报→复制到微信→一键拨120，形成完整的紧急处置闭环，而非停在"内容输出"层面。

### 7.2 技术难度 — 系统组合的深度

本项目的难度不在于任何单一技术点，而在于**系统级组合**。答辩时可主动说明：

| 层级 | 能力 | 技术代表 | 多数参赛者 | 本项目 |
|------|------|---------|-----------|--------|
| L1 | 单模型调用 | 调一次LLM API | ✅ | ✅ |
| L2 | 检索增强生成 | RAG + LLM | ✅ | ✅ |
| L3 | 双模型协同 | 文本LLM + 视觉LLM | 少见 | ✅ |
| L4 | 结构化约束输出 | JSON Schema强制 | 少见 | ✅ |
| L5 | 完整兜底体系 | 13种异常场景降级 | 稀有 | ✅ |
| L6 | 设计系统 | 3套主题全局CSS覆盖 | 稀有 | ✅ |
| L7 | 云端部署 | SSH + Streamlit Cloud | 部分 | ✅ |
| L8 | 工程化质量 | 缓存/日志/JSON解析器/线程安全 | 稀有 | ✅ |
| L9 | 单Agent工具调度 | Function Calling + 4Tool | 稀有 | ✅ |
| L10 | 流式输出+Schema校验 | SSE逐字生成 + JSON字段自动补全 | 稀有 | ✅ |

**为什么这更难**：单次API调用Demo一个下午能搭出来。但做到L5以上，每多一层，出问题的组合数就指数增长——文本模型超时怎么办、视觉模型超时怎么办、检索无结果怎么办、三者同时出问题怎么办？L8-L10（工程化质量+Agent调度+流式校验）进一步要求：重复请求能缓存、每次调用可追踪、LLM非标准输出能容错、并发访问不出竞态、用户一句话能自动路由到正确工具、长篇回答逐字流式呈现——这些不是功能需求，但决定了系统能不能像真正的产品一样运行。L5-L10的代码量只占总量的35%，但投入了超过一半的开发时间。

### 7.3 应用价值 — 方案可复制性

**换项目、换数据，方案能否平移？** 这是企业评委最关心的。本项目的架构设计保证了高度可复制：

| 组件 | 可替换方案 | 迁移示例 |
|------|-----------|---------|
| 知识库文档 | 更换`data/regulations/`下的TXT文件 | 桥梁工程规范 → 桥梁版安全Agent |
| System Prompts | 修改`utils/prompts.py`中的人设和领域 | 化工厂版、港航工程版、矿山安全版 |
| 紧急类型列表 | 修改`core/emergency_guide.py`中的`EMERGENCY_TYPES` | 新增"化学品泄漏""沉箱倾覆"等 |
| 培训工种/主题 | 修改`core/training_generator.py`中的列表 | 适配不同行业的工种体系 |
| 视觉检查要点 | 修改`utils/prompts.py`中的`VISION_SYSTEM_PROMPT` | 从"脚手架"改为"反应釜""管道"等 |
| UI主题 | 修改`ui_components.py`中的配色字典 | 适配企业VI色系 |
| 双模型管线 | 无需改动 | 文本+视觉的架构是行业通用的 |

**核心结论**：整个系统没有硬编码到"建筑安全"的逻辑——所有领域特定内容都在数据文件和Prompt文本中，更换一个行业只需要改数据和Prompt，代码零修改。

### 7.4 工程完整度 — 从Demo到产品

- **完整兜底体系**：13种异常场景均有降级策略，演示现场断网/输错/超时不翻车。评审不只是看你顺的时候多好，也看你翻车的时候多稳
- **运行时密钥管理**：`_read_api_key()` 支持环境变量和Streamlit Secrets双通道，本地开发与云端部署切换零修改
- **SSH部署链路**：绕过GFW对HTTPS的限制，稳定推送至GitHub + Streamlit Cloud自动部署
- **UI设计系统**：三套主题、全局CSS覆盖、移动端响应式——让裁判看到的不只是一个功能Demo，而是一个有设计意识的完整产品
